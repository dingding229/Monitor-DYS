# T39 · 整体重新设计：3 个视觉方向（Antigravity）

**先停止 T36。** 用户看了 v2.0 现在的实现，认为不好看、太单调（大面积白底灰字，卡片千篇一律，看不出这是一个「服务器监控探针」）。要求整体重构 UI，重新设计一个适合服务器监控探针的界面。

这一步**只做设计，不改 `src/`**。先出 3 个风格明显不同的方向给用户挑选，选定后再实现。

## 每个方向的交付
目录 `docs/design/v3/<a|b|c>/`：
- `prototype.html`：单文件静态原型（内联 CSS，无外部依赖；少量 JS 可以用来模拟实时跳动的数值和小图）。用写死的假数据，包含：首页（顶栏、总览、地图区域、筛选工具栏、至少 8 个节点：正常、高负载、离线、即将到期、无 ping 数据）和详情页（名称/状态区、实时指标、图表、Ping 探针选择）。
- 截图：`home-1440.png`、`home-390.png`、`detail-1440.png`。
- `README.md`：一句话定位、配色、字体、核心视觉元素，以及这个方向对性能的影响（例如是否需要额外的图形渲染）。

## 三个方向（请拉开差距，不要只是换颜色）
- **A · 运维控制台（深色优先）**：深色背景、高对比的状态色、霓虹感克制使用；总览像监控大屏（大数字 + 迷你趋势线）；节点卡片带 CPU/网络迷你折线（sparkline）或环形仪表；状态一眼可辨。
- **B · 现代仪表盘（浅色，有层次和色彩）**：浅色但不单调：主题色渐变点缀的头图区、彩色图标底块、环形/半环仪表、清晰的卡片分区；参考现代 SaaS 监控面板的观感。
- **C · 你自己提出的方向**：例如终端/等宽风、玻璃拟态的现代变体、Bento 网格大屏等，任选一种你认为最适合「服务器探针」的独特风格。

## 共同要求
- 一眼能看出是服务器监控探针：状态（在线/离线/告警）最醒目，资源占用用直观图形（环、条、迷你折线）表达，而不是只有文字和细进度条。
- 信息不能少：保留现在卡片上的所有信息（CPU/内存/硬盘/流量、实时速率、当期流量、到期与价格、延迟丢包），以及列表视图、地图、分组/地区/搜索/排序。
- 都要同时支持浅色和深色（A 以深色为主，B 以浅色为主）。
- 性能：图形用 CSS 或轻量的内联 SVG/canvas 实现，不引入新依赖；500 个节点时也要流畅（迷你图的实现方式要在 README 里说明，例如复用 ping 的 12 个桶或 WS 最近 N 帧）。
- 所有文字单行不折行；手机 390px 也要好看。
- 不要执行 git，只写 `docs/design/v3/**`。
